# Emberwick (working title) — Asset & Game Plan

A 2D top-down pixel art game built in Godot 4.7.1.

- **Godot:** `L:\SOFTWARE_2\Godot_v4.7.1-stable_win64.exe`
- **Art tooling:** Python 3.11 + Pillow (assets are generated by script)

## The game

A cozy action-adventure in the style of the top-down Zelda games. You play a young lantern-keeper in a small forest village. The lanterns that keep the night-mist away have gone out, and you explore the surrounding woods and an old ruin to relight them.

### Core loop

1. Talk to villagers to learn where a lantern shrine is.
2. Explore the overworld, fight mist creatures, and collect ember shards.
3. Push blocks, hit switches and find keys to reach the shrine.
4. Relight the lantern, which clears the mist from that area and opens the next path.

### Controls

- 4-direction movement
- Sword attack
- Interact (talk, open, read)
- One item slot (the lantern, which lights dark areas)

### Scope for the first playable slice

The village, one forest area, one small ruin, two enemy types and three NPCs.

## Art direction

| Setting | Choice | Reason |
|---|---|---|
| Tile size | 16×16 | Classic look, and fast to produce consistently |
| Characters | 16×24 | Taller than a tile, so they read as people |
| Viewport | 320×180, integer-scaled | Scales cleanly to 1080p |
| Palette | One fixed palette of about 32 colours | Keeps every asset cohesive |
| Style | Dark outlines, light from the top-left, 3 shades per material | Readable at small size |

## Asset list

### Tilesets

- **Overworld terrain:** grass, dirt path, water, sand and cliff, with a full 47-tile transition set for Godot's terrain autotiling, plus a few grass and flower variants.
- **Village:** house walls, roofs, doors, windows, fences, a bridge, a well and a signpost.
- **Ruin interior:** floor, walls, doorways, stairs, cracked wall, pit, pressure plate.
- **Animated tiles:** water (4 frames) and torch flame (4 frames).

### Main character (4 directions each)

- Idle: 2 frames
- Walk: 4 frames
- Sword attack: 3 frames
- Hurt: 1 frame, and a short death or collapse

### NPCs (idle and walk, 4 directions)

- Elder, who gives the quest
- Shopkeeper
- Child, who gives hints
- A cat for ambience

### Enemies

- Mist slime: hop, 4 frames
- Mist bat: fly, 4 frames
- Shade, a slower and tougher ruin enemy: 4 frames

### Props and objects

- Trees in 2 sizes, bushes (cuttable), rocks, pushable block, pots
- Chest (closed and open), locked door, key, floor switch
- Lantern shrine (unlit, and lit with animation)

### Items and effects

- Ember shard, heart, coin, key and potion icons
- Sword slash arc, hit spark, enemy dust puff, mist overlay

### UI

- Hearts (full, half, empty), an ember counter and an item slot frame
- A 9-slice dialogue box, an interact prompt and a small pixel font

## Production method

Each asset is drawn by a Python script that places pixels from the shared palette and exports PNG sprite sheets.

- **Consistency:** every sheet uses the same palette and shading rules.
- **Easy revisions:** changing a colour or proportion regenerates everything.
- **Quality bar:** clean, charming and cohesive, like a good game-jam asset pack, but not hand-polished commercial art.

A preview sheet is rendered and checked by eye after each batch.

## Godot setup

```
project.godot          (320×180, nearest-neighbour filtering, pixel snap)
assets/
  tilesets/  characters/  enemies/  props/  items/  fx/  ui/
tools/                 (the generator scripts and palette)
scenes/                (a test map, player, NPC)
```

- A `TileSet` resource with terrain sets and collision already configured
- `SpriteFrames` resources for the player, NPCs and enemies
- A small demo scene where you can walk around the village, so the assets are shown in use

## Build order

1. Palette and the generator framework
2. Overworld terrain tileset, then a preview for style approval
3. Main character
4. NPCs and enemies
5. Props, items, effects and UI
6. Village and ruin tilesets
7. Godot project, import settings, TileSet and SpriteFrames, demo scene

Step 2 is the checkpoint: changing the style is cheap before it and more expensive after.

## Open decisions

- **Theme:** cozy fantasy is the default; a sci-fi or post-apocalyptic setting fits the same asset structure.
- **Tile size:** 16×16 is recommended; 32×32 gives more detail but takes much longer and is harder to keep clean with generated art.
- **Demo scene:** a walkable demo with basic movement is included by default; it can be dropped for assets only.

## Status (all build steps done)

Everything in the build order is implemented and runs in Godot 4.7.1 (`Godot_v4.7.1-stable_win64_console.exe`, inside the folder named `Godot_v4.7.1-stable_win64.exe`).

### How to regenerate

```bash
cd tools
python gen_terrain.py && python gen_player.py && python gen_npcs.py && python gen_enemies.py
python gen_props.py && python gen_fx_ui.py && python gen_village_ruin.py
# then, from the project root, rebuild the Godot resources:
Godot_console --headless --path . --import
Godot_console --headless --path . --script res://scripts/editor/build_resources.gd
```

Contact sheets for every asset group are written to `tools/previews/`. Sheet layouts are described in `tools/build/*.json`.

### Where it differs from the plan

- **Palette:** 36 colours instead of ~32 (extra ember and mist tones).
- **Player frames:** 32×32 cells (16×24 body, feet anchored) so sword swings fit; NPCs, enemies and the cat use tight 16×24 / 16×16 cells.
- **Cliffs:** the rock face only appears on south-facing edges (ledge style). No west/east faces.
- **Font:** all-caps 5×7 bitmap font (BMFont `.fnt`); lowercase maps to capitals.
- **Extras added:** flagstone paving and a raised ruin-wall autotile set, village props (well, barrel, crate, lamp post), ruin props (pillars, rubble, cobweb), mist overlay and shadows.

### Demo (`scenes/main.tscn`)

Walk (WASD/arrows), attack (J/Space), talk/open (E/Enter). Village with three NPCs, river and bridge, the Mistwood with slimes and bats, and a ruin with shades, a chest and the lantern shrine; lighting the shrine lifts the mist and lights the village lamps.

### Known gaps

- The pit tile is decorative (no fall logic); the cobweb prop is drawn but not placed in the demo.
- Locked door, key, pushable block and floor switch art exist but have no gameplay scripts yet.
- Enemy AI and combat are deliberately minimal, and input was only tested through scripted runs, not by hand.

## Audio (OpenRouter: Lyria 3 + Gemini 3.8 Flash TTS)

`tools/gen_audio.py` is manifest-driven: music/jingles/SFX use `google/lyria-3-pro-preview` / `google/lyria-3-clip-preview`, voices use `google/gemini-3.8-flash-tts`. The key is read from the `OPENROUTER_API_KEY` environment variable and is never stored. Raw downloads are cached in `tools/_audio_tmp/raw`, so re-running never pays twice (`--force` regenerates). Costs are logged to `tools/build/audio_cost.log`.

```bash
export OPENROUTER_API_KEY=...        # then, from tools/:
python gen_audio.py sfx              # or: music | jingles | voices | <group> <names...>
```

In game, the `Audio` autoload (`scripts/game/audio.gd`) plays zone music with crossfades (village / mistwood / ruin), sound effects, jingles, and NPC voice lines (the dialogue text reveals in step with the voice). Missing files are skipped silently.

| Group | Status |
|---|---|
| Voices (Elder, Shopkeeper, Child) | all 10 lines |
| SFX | all 13: sword_swing, sword_hit, enemy_die, player_hurt, pickup_shard, pickup_heart, bush_cut, pot_break, chest_open, shrine_light, ui_blip, slime_hop, bat_flap |
| Jingles | shrine_lit (8 s), game_over (5.2 s) |
| Music | village (59 s), mistwood (55 s), ruin (56 s), all as seamless loops |

The model ignores requested lengths (jingles came back at 25-30 s) and its tracks end in silence, so `gen_audio.py` cuts jingles to their first phrase (`JINGLE_CUT`) and crossfades each track's ending into its start. This is done from the cached raw files, so tweaking it costs nothing. Sound effects were checked only by waveform analysis (length, level, envelope), not by ear.

Going forward, new sound effects are synthesized by script rather than generated with Lyria (user decision); Lyria stays for music and jingles.

Findings: Lyria requires `stream: true` and returns MP3 in one event; a Pro track costs about $0.08 and a clip about $0.04. Gemini TTS returns raw 24 kHz PCM only and reads inline style directions aloud, so voices use plain text with a distinct voice per character (Gacrux, Puck, Leda). OpenRouter refuses audio requests unless the key has at least $0.50 of limit remaining.

## Opening sequence (intro, house, diary, transitions)

The game now starts with a scripted intro (`scripts/game/intro.gd`); press **Esc** at any moment to skip to free play in the house.

1. Black screen with drifting embers: title "EMBERWICK" (with a bell chime), then four typed story cards. E/Space hurries a card along.
2. Eyelid transition: the keeper (asleep in bed, floating Zs) peeks twice, then opens his eyes and sits up. Cinematic bars slide in.
3. Inner thoughts (`thought` dialogue style: pale-blue text, tinted box, no voice).
4. He gets up, walks to the desk, and the diary opens: dimmed screen, book scales open, text is "written" line by line, page-turn sound before the right page.
5. More thoughts, bars slide out, HUD fades in and a "NEW OBJECTIVE" banner appears. Free play begins in the house; the door at the bottom leads to the village.

New pieces:
- `transition.gd` (autoload `Transition`): one shader for fade, pixel iris (used for doors), eyelid and dither dissolve, plus letterbox bars. The screen starts covered so there is never a flash of game.
- `house.gd` / `furniture.gd`: the interior (16x10 tiles, bed with asleep/sitting/empty states, hearth, desk, shelf, rug, windows with light shafts and dust). It sits far from the village (offset 2048,0) in the same scene and uses its own camera. Walking onto the doorstep of the western house enters it (iris wipe); the doorway inside leaves.
- `diary.gd`: also opens any time with **Tab** (or Q); reads story flags (`met_elder`, `entered_ruin`, `shrine_lit`) to tick tasks and change the notes. The desk in the house opens it too.
- Art: `tools/gen_interior.py` (interior tiles, props, diary book, checkbox, light shaft). Sound effects `page_turn`, `diary_open/close`, `bed_rustle`, `door_open/close`, `title_chime`, `wipe_whoosh` are synthesized by `tools/gen_sfx.py` (no AI generation, per the standing decision).
- Debug flags (after `--`): `--skip-intro`, `--autoplay` (auto-advance, faster), `--intro-shots=<dir>`, `--skip-after=<sec>`, `--door-shots=<dir>`, `--diary-shot=<file>`.

After a game over the screen fades to black, the scene reloads and fades back in, without replaying the intro.

### SFX revision (synthesized)

`sword_swing`, `sword_hit`, `pot_break` and `chest_open` were replaced with synthesized versions (`tools/gen_sfx.py`); the Lyria files are gone. Swing and hit have 3 variants each and the pot has 3, picked at random: `audio.gd` plays `<name>.wav` and/or `<name>_1..6.wav`, so more variants can be added by dropping in files. The swing is a swept band-pass noise (Doppler-style rise and fall) plus a faint steel ring; the hit is a thump, crack and metallic ring; the pot is a crack followed by ceramic tinks and a settling rattle; the chest is a latch click, wooden creak, lid thump and a rising chime with glitter.

## Title screen and pause menu

The game now opens on a title screen (`scenes/title.tscn` is the main scene); `scenes/main.tscn` is the game itself.

**Title** (`scripts/game/title.gd`): a night scene with a stepped-band sky, twinkling stars, moon, hills, trees lit by real `PointLight2D`s from the shrine and the keeper's lantern (a `CanvasModulate` darkens everything else), the keeper and the cat by the glowing shrine, rising embers, fireflies, scrolling mist, and the pixel logo (`tools/gen_title.py`). Menu: NEW GAME (dither-dissolve into the intro), OPTIONS, CREDITS (auto-scrolling), QUIT.

**Pause** (`scripts/game/pause_menu.gd`): Esc or P (not available during the intro or a door transition, or while a dialogue/diary is open). Freezes the game, dims the screen and low-passes the music. RESUME, DIARY, OPTIONS, CONTROLS, QUIT TO TITLE (with a STAY/LEAVE confirmation).

**Options** (`options_panel.gd`, shared by both menus): music / sound / voice volume in 10 steps (10 = as designed) and fullscreen. Saved to `user://settings.cfg` by the `Audio` autoload, so they persist between runs.

Menus use `menu_list.gd` (ember-shard cursor; W/S or arrows, Enter/E/Space, and the mouse). New sounds (synthesized): `menu_move`, `menu_select`, `menu_back`, `pause_in`, `pause_out`.

Testing a scene directly: `Godot --path . res://scenes/main.tscn -- --skip-intro`. More debug flags: `--auto-start` (title), `--shot=<file> [--state=options|credits]` (title), `--pause-shot=<file> --pause-state=main|options|controls|confirm`, `--key-test`, `--leave-test`.
